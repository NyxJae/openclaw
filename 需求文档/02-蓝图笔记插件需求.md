# 02-蓝图笔记插件需求

> 需求编号：02
> 版本：1.0
> 日期：2026-04-29

## 概述

蓝图笔记（Blueprint Notes）是 OpenClaw 的持久化路径绑定架构笔记系统。用于在开发过程中记录文件/文件夹的架构信息、职责范围、依赖关系、注意事项等，供 Agent 在读取文件时自动参考。

---

## 1. 系统定位

**核心原则：**
- 笔记是网络节点 — 记录框架级、架构级信息
- 禁止日志式记录 — 杜绝"修改了XX、处理了XX"等流水账
- Agent 可见、用户可读 — 人类可编辑的 JSON 格式

## 2. 存储方案

- **格式**：JSON（人类可读、可手动编辑）
- **存储路径**：`~/.openclaw/blueprint-notes/`
- **文件结构**：每个路径一个 `.json` 文件，路径中的 `/` 替换为 `%2F`（百分号编码，避免与文件名中原有的 `__` 冲突）

**数据模型：**
```json
{
  "path": "/home/ubuntu/project/src/main.py",
  "entries": [
    {
      "timestamp": "2026-04-29 14:32",
      "content": "Responsibility: ..."
    }
  ]
}
```

**读写模式：**
- `append`（默认）：追加新 entry，自动带时间戳分隔线
- `overwrite`：全量覆盖所有 entries

## 3. 工具设计（Agent 可调用）

| 工具 | 参数 | 行为 |
|------|------|------|
| `blueprint_set` | path, content, mode（append/overwrite，默认 append） | 创建或更新笔记 |
| `blueprint_delete` | path | 精确删除指定路径笔记，不级联 |
| `blueprint_query` | paths 或 keywords（二选一必填） | 查询笔记，返回完整内容不截断 |

## 4. 自动触发机制

- **并发安全**：依赖 OpenClaw hook runner 的串行执行机制，同一 hook 类型的回调不会并发，`pendingBlueprints` 数组无竞态风险。
- 笔记注入到工具结果消息内容尾部（`before_message_write` hook）

### 4.1 触发时机
- 监听 `read`、`read_file`、`read_many` 工具调用后（`after_tool_call` hook）——所有读取文件内容并返回文件内容的工具调用均触发
- 笔记注入到工具结果消息内容尾部（`before_message_write` hook）
- **并发安全**：依赖 OpenClaw hook runner 的串行执行机制，同一 hook 类型的回调不会并发，`pendingBlueprints` 数组无竞态风险

### 4.2 注入格式
```
[tool_result: 文件内容...]

📎 Blueprint Note [file:/path/to/file.py]: 职责: ...
📎 Blueprint Note [folder:/path/to/]: 职责: ...
```

### 4.3 递归策略
- 从文件路径向上逐级查询父文件夹笔记
- 每级有笔记就注入
- 遇到已加载过的文件夹级笔记 → 早停

### 4.4 去重策略
- 插件内存维护已加载路径 Set（路径级）
- 同一会话中，相同路径的笔记只注入一次
- 压缩后清空 Set（`after_compaction` hook）

### 4.5 压缩后行为
- 压缩范围内的笔记消息随工具结果一起被丢弃
- 去重 Set 清空，压缩后再次读取同文件会重新注入
- 极限情况：同一笔记在会话中存在不超过 2 次

## 5. 写入规范（软性约束）

### 5.1 推荐内容结构
```markdown
**Responsibility**: 该文件/文件夹应该做什么、不应该做什么、属于整体架构的哪个部分
**Outline**: 关键词、关键函数名等便于 grep 搜索的索引
**Dependencies**: 相关文档、相关代码等文件的路径指针（如"参见 /project/docs/arch.md"）
**Caveats**: 边界情况、已知坑点、变更风险
```

### 5.2 MUST NOT — 禁止行为
- ❌ 日志式记录 — 不得出现"修改了XX、处理了XX、修复了XX"等时间线流水账
- ❌ 记录具体代码实现细节 — 代码会变动，笔记记录"为什么这样设计"而非"代码怎么写"

### 5.3 SHOULD — 推荐行为
- 优先使用 append 模式追加，定期整理时使用 overwrite
- 文件夹笔记记录该目录的整体设计意图，文件笔记记录具体实现约束

## 6. 实现架构（OpenClaw 插件）

### 6.1 插件名：`blueprint-notes`

### 6.2 Hook 注册
- `after_tool_call` → 监听读文件 → 查笔记 → 暂存
- `before_message_write` → 取暂存 → 注入消息 → 清空暂存
- `after_compaction` → 清空已加载路径 Set

### 6.3 工具注册
- `registerTool("blueprint_set")`
- `registerTool("blueprint_query")`
- `registerTool("blueprint_delete")`

### 6.4 状态管理
- `loadedPaths: Set<string>` — 已加载文件夹路径（会话级去重）
- `pendingBlueprints: Array<{path, content}>` — 本轮待注入的笔记

## 7. 举例说明

### 场景 1：Agent 记录架构笔记

**输入：** Agent 完成对一个模块的分析后，调用 `blueprint_set`
```
blueprint_set(
  path: "/home/ubuntu/project/src/http/client.py",
  content: "Responsibility: HTTP client wrapper with retry. Does NOT handle auth.\nOutline: retry_policy, http_post, http_get\nDependencies: See /project/src/config/network.py\nCaveats: Retry count hardcoded to 3.",
  mode: "append"
)
```

**预期行为：** 笔记写入 `~/.openclaw/blueprint-notes/%2Fhome%2Fubuntu%2Fproject%2Fsrc%2Fhttp%2Fclient.py.json`
```json
{
  "path": "/home/ubuntu/project/src/http/client.py",
  "entries": [
    {
      "timestamp": "2026-04-29 14:32",
      "content": "Responsibility: HTTP client wrapper with retry. Does NOT handle auth.\nOutline: retry_policy, http_post, http_get\nDependencies: See /project/src/config/network.py\nCaveats: Retry count hardcoded to 3."
    }
  ]
}
```

**反例（错误行为）：**
```
日志式记录："2026-04-29 修改了 client.py 的重试逻辑，从 3 次改为 5 次"
❌ 这违反了禁止日志式记录的原则，应该记录"为什么重试 5 次"而非"改了什么"
```

---

### 场景 2：Agent 读文件自动注入笔记

**输入：** Agent 调用 `read_file("/home/ubuntu/project/src/http/client.py")`

**上下文：** 该文件和父文件夹已有笔记：
- `/home/ubuntu/project/src/http/client.py` → "HTTP client wrapper..."
- `/home/ubuntu/project/src/http/` → "HTTP 模块：所有 HTTP 客户端实现，不含业务逻辑"
- `/home/ubuntu/project/src/` → "核心源码目录"

**预期输出（注入到工具结果后）：**
```
[tool_result: 文件内容...]

📎 Blueprint Note [file:/home/ubuntu/project/src/http/client.py]:
  Responsibility: HTTP client wrapper with retry. Does NOT handle auth.
  Outline: retry_policy, http_post, http_get
  Dependencies: See /project/src/config/network.py
  Caveats: Retry count hardcoded to 3.

📎 Blueprint Note [folder:/home/ubuntu/project/src/http/]:
  Responsibility: HTTP 模块：所有 HTTP 客户端实现，不含业务逻辑

📎 Blueprint Note [folder:/home/ubuntu/project/src/]:
  Responsibility: 核心源码目录
```

**反例（错误行为）：**
```
[tool_result: 文件内容...]
（无任何笔记注入）
❌ 该路径有笔记但未被注入，Agent 缺少架构上下文
```

---

### 场景 3：同文件多次读取，去重生效

**输入：** 同一会话中第二次调用 `read_file("/home/ubuntu/project/src/http/client.py")`

**预期输出：**
```
[tool_result: 文件内容...]
（无笔记注入 — 该路径的笔记在第一次读取时已加载过）
```

**反例（错误行为）：**
```
[tool_result: 文件内容...]
📎 Blueprint Note [file:/home/ubuntu/project/src/http/client.py]: ...
📎 Blueprint Note [folder:/home/ubuntu/project/src/http/]: ...
📎 Blueprint Note [folder:/home/ubuntu/project/src/]: ...
❌ 重复注入相同笔记，导致上下文膨胀
```

---

### 场景 4：会话压缩后重新加载

**输入：** 长会话触发压缩（compaction），压缩后再次调用 `read_file("/home/ubuntu/project/src/http/client.py")`

**预期输出：**
```
[tool_result: 文件内容...]
📎 Blueprint Note [file:/home/ubuntu/project/src/http/client.py]: ...
📎 Blueprint Note [folder:/home/ubuntu/project/src/http/]: ...
📎 Blueprint Note [folder:/home/ubuntu/project/src/]: ...
（笔记重新注入 — 压缩后清空了去重表，这是预期行为）
```

**说明：** 极限情况，同一笔记在完整会话中最多出现 2 次（压缩前 1 次 + 压缩后 1 次），笔记通常很短，代价可接受。

---

### 场景 5：查询笔记

**输入：** Agent 调用 `blueprint_query(keywords: ["HTTP", "retry"])`

**预期输出：**
```
/home/ubuntu/project/src/http/client.py:
  Responsibility: HTTP client wrapper with retry. Does NOT handle auth.
  Outline: retry_policy, http_post, http_get
  Dependencies: See /project/src/config/network.py
  Caveats: Retry count hardcoded to 3.
```

**反例（错误行为）：**
```
/home/ubuntu/project/src/http/client.py:
  Responsibility: HTTP client... [truncated]
❌ 笔记内容被截断，Agent 无法获取完整约束信息
```

## 8. 边界情况

| 场景 | 预期行为 |
|------|---------|
| `blueprint_set` 路径已存在，mode=append | 自动加时间戳追加 |
| `blueprint_set` 路径已存在，mode=overwrite | 全量覆盖 |
| `blueprint_delete` 路径不存在 | 返回错误 |
| `blueprint_query` 无匹配 | 返回空列表 |
| 读取文件时该文件无笔记 | 不注入任何笔记 |
| 所有父文件夹均无笔记 | 不注入任何笔记 |
| 会话级去重表丢失/重置 | 重新注入（幂等） |
| 压缩后笔记重新发送 | 可接受（笔记简短） |

## 9. 决定记录

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 存储格式 | JSON | 人类可读可编辑 |
| 2 | 触发范围 | `read`/`read_file`/`read_many` | 所有读取文件内容的工具调用均触发，避免遗漏批量读取场景 |
| 3 | 注入时机 | 紧跟工具结果 | LLM 立即看到 |
| 4 | 笔记内容格式 | 软性约束 | 允许自由发挥，明确禁止日志 |
| 5 | 工具暴露 | 工具 + 自动触发 | 两者都要 |
| 6 | 递归去重 | 会话级去重 + 早停 | 已确认逻辑 |
| 7 | 存储路径 | `~/.openclaw/blueprint-notes/` | 随 OpenClaw 走 |
| 8 | 压缩后恢复 | 清空去重表 | 极限最多重复 2 次 |
| 9 | 压缩触发 | `after_compaction` hook | 主动清空，语义明确 |
| 10 | 路径编码 | 百分号编码（`/` → `%2F`） | 避免与文件名中原有 `__` 冲突，标准可逆 |
| 11 | 并发安全 | 依赖 hook runner 串行执行 | 同一 hook 类型不会并发回调，无需额外加锁 |
