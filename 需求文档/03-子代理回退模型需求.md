# 03-子代理回退模型需求

> 2026-04-29 讨论确定

## 背景

### 问题

子代理（通过 `sessions_spawn` 创建）当前只能拿到一个主模型字符串，没有回退链。即使配置了 `subagents.model.fallbacks`，也因为 `normalizeModelSelection()` 只读 `primary`、子代理 spawn 流程不传 `fallbacksOverride` 而被静默丢弃。

后果：主模型（如 Kimi）401 / 429 时，子代理直接 fail，不会像主 Agent 那样自动切到 fallback 模型。

### GitHub 相关讨论

- [#57900](https://github.com/openclaw/openclaw/issues/57900) 子代理不走 fallback 链（已标记为已修复，但实际只覆盖了 429 场景的部分路径）
- [#29496](https://github.com/openclaw/openclaw/pull/29496) 有人尝试加 `resolveSubagentSpawnModelFallbacks()`，因上游重构关闭未合并
- 当前 `main` 分支（2026.4.26）源码确认：子代理 fallback 全链路缺失

## 需求范围

为子代理添加回退模型支持，**不改动现有主模型选择逻辑**。两条链独立：

- **主模型链**：现有逻辑，完全不动
- **回退链**：新增，只在 `subagents` 和 `defaults.model` 范围内查找

## 主模型链（现有，不动）

```
① modelOverride（sessions_spawn 手动传的 model 参数）
② per-agent subagents.model.primary
③ per-agent model.primary
④ defaults subagents.model.primary
⑤ defaults model.primary
```

走第一级有值即停止，返回单一模型字符串。

## 回退链（新增）

与主模型链分离，独立查找：

```
① per-agent subagents.model.fallbacks
② defaults subagents.model.fallbacks
③ defaults model.fallbacks
```

走第一级有值即停止，返回 `string[]`。

## 去重规则

回退链的 `fallbacks[]` 中，跳过与主模型链结果相同的条目（`provider/model` 完全匹配）。

- 不合并多级 fallbacks（找到第一级有值就停）
- 不去重 fallbacks 内部的重复项（信任配置）

## 最终组装

```
primary = 主模型链结果
fallbacks = 回退链结果（已去重 primary）
→ 传给 runner 的 runWithModelFallback(primary, fallbacks)
```

`runWithModelFallback` 是主 Agent 已有的回退执行机制（逐个尝试候选项），子代理复用它，不需要新增执行逻辑。

## 配置示例

```json5
{
  agents: {
    defaults: {
      model: {
        primary: "kimi/kimi-code",
        fallbacks: ["deepseek/deepseek-v4-pro"]
      },
      subagents: {
        model: {
          primary: "kimi/kimi-code",
          fallbacks: ["deepseek/deepseek-v4-pro", "deepseek/deepseek-v4-flash"]
        }
      }
    }
  }
}
```

### 举例一：subagents.model 配了回退

| 条件 | 值 |
|------|-----|
| 主模型链结果 | `kimi/kimi-code`（从 defaults.subagents.model.primary） |
| 回退链结果 | `["deepseek/deepseek-v4-pro", "deepseek/deepseek-v4-flash"]`（从 defaults.subagents.model.fallbacks） |
| 去重后 | 无变化（主模型不在 fallbacks 里） |
| 最终 | primary=`kimi/kimi-code`, fallbacks=`[deepseek-v4-pro, deepseek-v4-flash]` |

**行为**：Kimi 401 → 自动切 DeepSeek V4 Pro → 还不行切 DeepSeek V4 Flash

### 举例二：没配 subagents.model.fallbacks

| 条件 | 值 |
|------|-----|
| 主模型链结果 | `kimi/kimi-code`（从 defaults.subagents.model.primary） |
| 回退链结果 | `["deepseek/deepseek-v4-pro"]`（从 defaults.model.fallbacks） |
| 去重后 | 无变化 |
| 最终 | primary=`kimi/kimi-code`, fallbacks=`[deepseek-v4-pro]` |

**行为**：Kimi 401 → 自动切 DeepSeek V4 Pro

### 举例三：手动传了 model

```json
sessions_spawn({ task: "...", model: "deepseek/deepseek-v4-flash" })
```

| 条件 | 值 |
|------|-----|
| 主模型链结果 | `deepseek/deepseek-v4-flash`（modelOverride 优先） |
| 回退链结果 | `["deepseek/deepseek-v4-pro", "deepseek/deepseek-v4-flash"]` |
| 去重后 | `["deepseek/deepseek-v4-pro"]`（deepseek-v4-flash 已去重） |
| 最终 | primary=`deepseek-v4-flash`, fallbacks=`[deepseek-v4-pro]` |

**行为**：DeepSeek Flash 挂了 → 回退到 DeepSeek V4 Pro

### 举例四：没配任何 subagents.model

| 条件 | 值 |
|------|-----|
| 主模型链结果 | `kimi/kimi-code`（从 per-agent model.primary / defaults model.primary） |
| 回退链结果 | `["deepseek/deepseek-v4-pro"]`（从 defaults.model.fallbacks） |
| 去重后 | 无变化 |
| 最终 | primary=`kimi/kimi-code`, fallbacks=`[deepseek-v4-pro]` |

**行为**：和主 Agent 一样的回退体验（Kimi → DeepSeek）

### 反例：配了 subagents.model.fallbacks 但和 primary 重复

```json5
{
  subagents: {
    model: {
      primary: "deepseek/deepseek-v4-flash",
      fallbacks: ["deepseek/deepseek-v4-flash", "deepseek/deepseek-v4-pro"]
    }
  }
}
```

| 条件 | 值 |
|------|-----|
| 去重后 | `["deepseek/deepseek-v4-pro"]`（deepseek-v4-flash 因和 primary 重复被跳过） |

## 涉及文件（预估）

| 文件 | 改动 |
|------|------|
| `src/agents/model-selection.ts` | 新增 `resolveSubagentSpawnModelFallbacks()`，镜像 fallback 级联 |
| `src/agents/subagent-spawn-plan.ts` | `resolveSubagentModelAndThinkingPlan` 返回 fallbacks |
| `src/agents/subagent-spawn.ts` | spawn 和 session patch 传递 fallbacks 到 runner |
| 测试文件 | 新增 fallback 级联 + 去重 + 端到端 401/429 回退的测试用例 |

## 不在范围内

- 不修改 `resolveEffectiveModelFallbacks`（agent-scope.ts）— 那是主 Agent 专用
- 不修改 `normalizeModelSelection` — 保持现有行为
- 不合并多级 fallbacks
- 不增加新的配置字段
